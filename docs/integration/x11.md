# X11 后端构建和接入

HGS 1.2 的 X11 后端使用 wlroots 0.20.2、Xwayland 24.1.13 和独立的 OHOS 原生子进程。现有 Wayland 后端继续使用原来的协议和窗口宿主。带 X11 能力的包可以选择 `wayland`、`x11` 或 `both`。双协议各有独立的逻辑输出和协议事件循环。

## ARM64 构建

为 HAR 的 native CMake 传入 `-DHGS_BUILD_X11=ON -DHGS_X11_DEPS_ROOT=/absolute/ohos-x11-sdk`。默认构建维持原 Wayland 配置。SDK 前缀需要以下输入：

- `include/wlroots-0.20`、`include/pixman-1`、XCB、xkbcommon 及与 wlroots 构建匹配的 Wayland 头。
- `lib/libwlroots-0.20.a`。使用 WineHua 基线所验证的 OHOS wlroots 补丁组合，其中 `wlr_xwayland_create_with_server` 管理 Xwayland shell 与 XWM。HGS 自己分配监听、启动 NCP、观察子进程并回收 fd。
- 同一套 OHOS ARM64 构建的 Wayland、XCB、pixman、libdrm、xkbcommon 和 `libxwayland_ohos.so`，以及它们的运行依赖。

`scripts/x11/stage_runtime.py` 从显式给出的多个库目录解析 ELF 的 NEEDED 闭包。把 SDK 库目录放在第一位，额外目录用于补齐它不包含的运行库，例如 libfreetype。将结果放入独立的 HAR 打包目录：

```sh
python3 scripts/x11/stage_runtime.py \
  --lib-dir /absolute/ohos-x11-sdk/lib \
  --lib-dir /absolute/additional-ohos-runtime-libs \
  --root-library /absolute/native-build/libhgs.so \
  --output /absolute/clean-hgs-arm64-runtime
```

同时打包 CMake 产出的 `libhgs.so`、`libhgs_xwayland_child.so` 与常规 OHOS C++ 运行库。以最终 HAP 中实际的 SONAME 为准。同一个 Wayland 或 xkbcommon SONAME 只使用一份匹配 SDK 的提供者。

## 资源和启动

`scripts/x11/pack_resources.sh XKB_ROOT OUTPUT_ZIP` 使用宿主 xkbcomp 从指定的 xkeyboard-config 目录打包规则并生成 US 布局的预编译 XKM。宿主将压缩包解到自己的可写目录，然后把路径交给服务：

```ts
const base = context.filesDir;
const session = await HgsService.create().start({
  protocols: 'both',
  composition: 'per-window',
  runtimeDir: base + '/hgs-runtime',
  wayland: { socketName: 'hgs-wayland' },
  x11: {
    xkbRoot: base + '/hgs-x11/xkb',
    keymapPath: base + '/hgs-x11/keymap.xkm',
    startupTimeoutMs: 5000
  }
});
const x11 = session.clientEnvironment('x11');
```

宿主创建 `runtimeDir` 的父目录。X11 只监听标准 abstract AF_UNIX 地址，从 `:0` 至 `:32` 选择第一个空闲编号。每次启动生成私有的 Xauthority cookie 和按 display 编号命名的 XKM。客户端继承 `x11.set` 中的 DISPLAY、XAUTHORITY，并移除 `x11.unset` 所列变量。NCP 客户端需要显式传递这些值。启动配置和子进程资源路径都由调用方提供，Xwayland 不依赖宿主进程的 XDG_RUNTIME_DIR。

Ready 表示逻辑输出和 XWM 握手已就绪。异步门面依序执行启停。资源缺失或 Xwayland 启动失败会回滚本次启动的后端。运行中 Xwayland 断开会撤销端点并发出 `backend-disconnected`，其他已就绪的后端可以继续使用。调用 stop 会关闭服务线程和本次启动的原生子进程通道，清理私有认证文件。

当前 X11 可映射真实窗口并通过 seat 注入键鼠。逻辑输出由 pixman 承载，OHOS surface 呈现、混合窗口焦点、XIM 以及 Wine 外部帧接入仍待实现。显式请求 X11 DesktopRoot 会返回结构化错误。测试客户端的 XGetImage 读回验证的是 X11 绘图结果。
