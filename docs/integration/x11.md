# X11 后端构建和接入

HGS 的 X11 后端使用 wlroots 0.20.2、Xwayland 24.1.13 和独立的 OHOS 原生子进程。带 X11 能力的包可以选择 `wayland`、`x11` 或 `both`。双协议各有独立的逻辑输出和协议事件循环。

## ARM64 构建

为 HAR 的 native CMake 传入 `-DHGS_BUILD_X11=ON -DHGS_X11_DEPS_ROOT=/absolute/ohos-x11-sdk`。默认构建维持原 Wayland 配置。SDK 前缀需要以下输入：

- `include/wlroots-0.20`、`include/pixman-1`、XCB、xkbcommon 及与 wlroots 构建匹配的 Wayland 头。
- `lib/libwlroots-0.20.a`。使用 WineHua 基线所验证的 OHOS wlroots 补丁组合，其中 `wlr_xwayland_create_with_server` 管理 Xwayland shell 与 XWM。HGS 自己分配监听、启动 NCP、观察子进程并回收 fd。
- 同一套 OHOS ARM64 构建的 Wayland、XCB、pixman、libdrm、xkbcommon 和 `libxwayland_ohos.so`，以及它们的运行依赖。

`scripts/x11/stage_runtime.py` 从显式给出的多个库目录解析 ELF 的 NEEDED 闭包。把 SDK 库目录放在第一位，额外目录用于补齐它不包含的运行库，例如 libfreetype。将结果放入独立的 HAR 打包目录：

```sh
python3 scripts/x11/stage_runtime.py \
  --lib-dir /absolute/ohos-x11-sdk/lib \
  --lib-dir /absolute/additional-ohos-runtime-libs \
  --root-library /absolute/native-build/libhgs.so \
  --output /absolute/clean-hgs-arm64-runtime
```

同时打包 CMake 产出的 `libhgs.so`、`libhgs_xwayland_child.so` 与常规 OHOS C++ 运行库。以最终 HAP 中实际的 SONAME 为准。同一个 Wayland 或 xkbcommon SONAME 只使用一份匹配 SDK 的提供者。

宿主通过动态加载使用的 X11 客户端库，需要以 `--dlopen-library SONAME` 显式加入闭包。WineHua 的 Box64 测试包使用 `--dlopen-library libXext.so.6 --dlopen-library libX11-xcb.so.1`，与 HGS 使用同一套 ARM64 Xlib 和 XCB。只扫描 ELF 的 NEEDED 项会漏掉这两个库。

## 资源和启动

`scripts/x11/pack_resources.sh XKB_ROOT OUTPUT_ZIP` 使用宿主 xkbcomp 从指定的 xkeyboard-config 目录打包规则并生成 US 布局的预编译 XKM。宿主将压缩包解到自己的可写目录，然后把路径交给服务：

```ts
const base = context.filesDir;
const session = await HgsService.create().start({
  protocols: 'both',
  composition: 'per-window',
  runtimeDir: base + '/hgs-runtime',
  wayland: { socketName: 'hgs-wayland' },
  x11: {
    xkbRoot: base + '/hgs-x11/xkb',
    keymapPath: base + '/hgs-x11/keymap.xkm',
    startupTimeoutMs: 5000
  }
});
const x11 = session.clientEnvironment('x11');
```

宿主创建 `runtimeDir` 的父目录。X11 只监听标准 abstract AF_UNIX 地址，从 `:0` 至 `:32` 选择第一个空闲编号。每次启动生成私有的 Xauthority cookie 和按 display 编号命名的 XKM。客户端继承 `x11.set` 中的 DISPLAY、XAUTHORITY，并移除 `x11.unset` 所列变量。NCP 客户端需要显式传递这些值。启动配置和子进程资源路径都由调用方提供，Xwayland 不依赖宿主进程的 XDG_RUNTIME_DIR。

Ready 表示逻辑输出和 XWM 握手已就绪。异步门面依序执行启停。资源缺失或 Xwayland 启动失败会回滚本次启动的后端。运行中 Xwayland 断开会撤销端点并发出 `backend-disconnected`，其他已就绪的后端可以继续使用。调用 stop 会关闭服务线程和本次启动的原生子进程通道，清理私有认证文件。

X11 可映射真实窗口并通过 seat 注入键鼠。宿主可将会话的 `window.id` 和 `epoch` 传给 `HgsWindowSurface`，在 ArkUI 中显示该窗口。自管 XComponent 的宿主可在 Surface 创建和销毁时分别调用 `session.bindSurface(windowId, surfaceId, true)` 和 `session.bindSurface(windowId, surfaceId, false)`。返回值表示命令是否进入 X11 事件队列。解除绑定时会校验 Surface ID，X11 窗口取消映射或会话停止时也会释放绑定。

给 `HgsWindowSurface` 传入 `interactive: true` 可接收键盘、鼠标、滚轮和单指触摸。触摸映射为左键，坐标按 XComponent 归一化，X11 事件线程按当前 surface 尺寸换算。直接使用 `session.sendInput` 的 X11 宿主也可以在指针或滚轮事件上使用 `normalizedPosition: true`，此时坐标范围为 `[0, 1]`。省略该字段时继续使用逻辑窗口坐标。

每窗口呈现读取 Xwayland 提交的 CPU 可读缓冲，经 pixman 转成 RGBA 写入 OHOS Surface 队列。队列繁忙时允许丢帧，避免阻塞 X11 事件循环。显式请求 X11 DesktopRoot 会返回结构化错误。ArkTS 默认宿主接入见 [公共服务 API](../api/service-api.md#默认窗口宿主)。

原生宿主可在服务启动前通过 `Hgs_setExternalFrameProvider` 注入 `hgs::service::ExternalFrameProvider`。HGS 用 XID、客户端 PID 和窗口代次匹配可用帧源，并在绑定的 OHOS Surface 上呈现。帧源未就绪时继续使用 CPU 缓冲，解绑或窗口取消映射时释放该代次的 GPU 资源。Provider 的生命周期需覆盖运行中的服务，原生接口定义于 `include/hgs/external_frames.h`。

## XIM 输入法

使用 `bash scripts/x11/build_xim.sh OHOS_NATIVE_SDK X11_SDK XCB_IMDKIT_CHECKOUT XCB_UTIL_ARCHIVE OUTPUT_PREFIX` 构建依赖。脚本校验 xcb-imdkit 1.0.9 checkout 和 xcb-util 0.4.1 源码归档。源码见 [xcb-imdkit](https://github.com/fcitx/xcb-imdkit/tree/1.0.9) 和 [xcb-util](https://xorg.freedesktop.org/archive/individual/xcb/xcb-util-0.4.1.tar.xz)。

将 `-DHGS_BUILD_XIM=ON -DHGS_XIM_DEPS_ROOT=OUTPUT_PREFIX` 加入 HAR 的 native CMake 参数。打包时包含 `libhgs_xim_child.so`，同时把该库传给 `stage_runtime.py --root-library`，把 XIM SDK 的 lib 目录传给 `--lib-dir`。XIM helper 使用本次会话的 DISPLAY 和认证文件，准备完成后才发布 endpoint。

宿主用 `x11.imeServerName` 启用该会话的 XIM。客户端从 `clientEnvironment('x11')` 继承 `XMODIFIERS`，并按自己的 Xlib 构建配置 locale 目录。XIM 文本控件获得焦点后，HGS 窗口快照的 `textInputActive` 变为 true，宿主可以调用 `session.commitText(windowId, text)` 提交 UTF-8 文本。XIM 负责提交已确认文本，系统输入法保留候选与预编辑。
